## תהליך ריצה יומית

### שלב 1 — עיבוד תשובות של איציק
1. חפש ב-Gmail שרשורים עם `subject:"[רדאר אירועים]"` מ-7 הימים האחרונים שיש בהם תשובה מ-itzikiluz28@gmail.com.
2. פענח כל שורה בתשובה (N = מספר הפריט במייל, התאם לפי ה-ID בלוג):
   - `כן N` / `נרשמתי N` → עמודת "החלטת איציק" = מעוניין / נרשם.
   - `לא N` + סיבה → "לא רלוונטי" + הסיבה. אם הסיבה מלמדת כלל כללי (למשל "בלי אירועי פינטק"), הוסף כלל ל-`learnings.md`.
   - `עוד כמו N` → הוסף ל-`learnings.md` שזה סוג אירוע מועדף.
   - טקסט לא ברור → אל תנחש; שאל בראש המייל הבא.
3. פריט שלא נענה נשאר "ממתין".

### שלב 2 — סריקה
1. עבור על כל המקורות ב-`sources.md` (WebFetch לדפי לוח אירועים).
2. בצע 6–10 חיפושי רשת משתנים (ראה רשימת מחרוזות ב-`sources.md`), בעברית ובאנגלית. גוון את המחרוזות מיום ליום כדי לא לקבל אותן תוצאות.
3. לכל מועמד חלץ: שם, מארגן, תאריך ושעה (שעון ישראל), מיקום / אונליין, מחיר אם ידוע, תקציר אג'נדה, קישור הרשמה ישיר.
4. **אמת כל פריט בדף האירוע עצמו** לפני שהוא נכנס למייל: תאריך עתידי, קישור הרשמה עובד, הרשמה פתוחה. פריט שלא אומת → סטטוס "במעקב" ולא נשלח.

### שלב 3 — מניעת כפילות (חובה)
- **מפתח:** שם האירוע המנורמל + תאריך. אם המפתח כבר בלוג בכל סטטוס — דלג. אל תציג שוב פריט שנשלח, נפסל או נבדק.
- **חריגים שמותר להציג שוב:** פריט "במעקב" שעכשיו נפתחה בו הרשמה / נוסף קישור / אג'נדה שמשנה את הציון. במקרה כזה עדכן את אותה שורה (לא שורה חדשה) וסמן במייל "עדכון".
- **מקורות שנבדקו:** עדכן את טבלת "מקורות שנבדקו" בלוג עם תאריך הבדיקה. מקור שנבדק היום ולא מתעדכן מהר (לוח חודשי) — אפשר לדלג עליו עד 3 ימים.

### שלב 5 — מייל יומי
שלח מייל HTML ל-itzikiluz28@gmail.com בלבד, בעברית RTL, לפי `templates.md`.
- כותרת: `[רדאר אירועים] {N} חדשים — {DD/MM}`.
- סדר: כנסים בישראל (לפי תאריך) → וובינרים ואונליין → עדכונים לפריטים במעקב → גבוליים בשורה אחת כל אחד.
- אם אין שום פריט חדש: מייל קצר בשורה אחת `[רדאר אירועים] אין חדש — {DD/MM}` + מה נבדק.
- **תזכורות:** פריט שאיציק סימן "מעוניין" ועדיין לא "נרשם", ומועד ההרשמה המוקדמת / האירוע בעוד 7 ימים או פחות — הוסף בראש המייל תחת "לא לשכוח".

### שלב 6 — לוג
1. הוסף ל-`events-log.md` שורה לכל פריט שנבדק — כולל נפסלים וגבוליים — ועדכן "ריצה אחרונה" ו"מקורות שנבדקו".
2. פריט שתאריכו עבר: שנה סטטוס ל"עבר" (אל תמחק שורות).
3. commit אחד ל-`main` עם ההודעה `events-radar: run {YYYY-MM-DD}`. לפני ה-push: `git fetch origin main` ו-rebase.
4. אם ה-push נכשל: הוסף את שורות הלוג בתחתית המייל תחת "לא נשמר ב-repo".
5. אל תשנה בעצמך את `sources.md` או את SKILL.md. המלצות (מקור חדש שכדאי להוסיף, מקור מת) — בסוף המייל.
