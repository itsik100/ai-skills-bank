# תבניות — בדיקת אפקטיביות והפקת ערך

## תבנית 1: פגישת סטטוס עם Owner (שלב א')

```
נושאים לפגישת סטטוס:
1. מדדי שימוש כמותיים (כניסות, פניות פתוחות/סגורות, שינוי לעומת התחלה)
2. הערכת % התקדמות מול היעד שהוגדר ב-needs-diagnosis
3. חסמים ידועים (טכניים: אינטגרציות/דיוק נתונים; אנושיים: התנגדות)
4. תוכנית מדידה מעמיקה יותר (סקר? לאיזה קהלים?)
```

## תבנית 2: סקר כפול-קהל (שלב ב')

לבנות **שאלון נפרד לכל קהל** (לפחות: משתמש קצה חיצוני, נציג/עובד פנימי). כל שאלון בודק את חמש העצמות, בשפה מותאמת לקהל:

```
לקהל חיצוני (לקוחות/משתמשי קצה):
- האם המערכת עוזרת לך למצוא מה שחיפשת? (Usefulness)
- האם קל להשתמש? (Usability)
- האם היית פונה קודם למערכת, או ישר לנציג אנושי? למה? (Self-Efficacy)
- מה חסר לך? (Facilitating Conditions — פתוח)

לקהל פנימי (עובדים/נציגים):
- האם המערכת עוזרת לך בעבודה היומיומית? (Usefulness)
- האם היא משתלבת בזרימת העבודה שלך? (Usability/Facilitating Conditions)
- האם עמיתים/מנהלים משתמשים בה? (Social Influence)
- מה חסר טכנית (אינטגרציות, נתונים)? (Facilitating Conditions)
```

אם קצב המענה נמוך — להציע גרסה ידידותית יותר (למשל דרך Monday) במקום לוותר.

## תבנית 3: דוח המלצות

```
בדיקת אפקטיביות — [שם המערכת/הפרויקט]
לקוח: [שם]
תאריך: [DD/MM/YYYY]

1. רקע: מה נמדד ולמה עכשיו
2. מתודולוגיה: מדגם (גודל + הרכב לכל קהל), מקורות (פגישת סטטוס + סקרים)

3. ממצאים לפי קהל:
   [קהל א']
   ★★★★★ [עצם] — [ממצא]
   ...
   → העצם המובילה: [שם] — [הסבר קצר]
   → הבחנה סימפטום/שורש: "אם הייתי מסתכל רק על [X], הייתי מסיק [Y].
      לפי תרשים הדג, [X] הוא הסימפטום, לא הבעיה."

   [קהל ב']
   (אותו מבנה)

4. המלצות — ממוקדות בעצם המובילה לכל קהל, לא בסימפטום שדווח

5. סיכום: מה יחזור להימדד, מתי (תזמון ה-check-in הבא)
```
